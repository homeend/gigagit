# gg web F4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline, this session).

**Goal:** the six F4 rows of the parity doc. **Spec:** docs/superpowers/specs/2026-10-24-web-f4-design.md

## Global Constraints

- TUI words verbatim; web English only. No global `.hidden` rule: every hideable element gets its own `#id.hidden`.
- `go test ./internal/web` after every static edit. Pure functions node-tested via `jsFunc`; wiring by source pins.

## Review Focus

- A stash filter kept across a live refresh of the list (rows re-render, the filter must hold).
- Settings type-to-filter must never steal keys typed into a Settings field.
- `alt+x` must not fire while a console has the keys (keys-to-session).
- ◇ Staged: cursor / index math with two pseudo-rows (shift-click runs, marks, keys, live re-anchor).
- List notes on a stack with unread files.

2. Find current — `findCurrentRow(kind)` pure decision (`currentRowOutcome`), header `⌖` buttons, palette rows. Tests: node outcome words; pins.
3. Settings filter — `settingsRowMatch`, `applySettingsFilter`, type-to-filter + esc order. Tests: node match; pins.
4. Cheat sheets — `tokensHelp(now, text)` (tokenhelp.js), ctrl+d + button in both forms, alt+x. Tests: node lines vs TUI; pins.
5. List notes — `noteListEntries`, `noteListLine`, overlay `notelist.js`, menu rows. Tests: node; pins.
6. ◇ Staged row — `stagedCount`, `pseudoKind(i)`, `wtCount` 0–2, row HTML, click/mark/compare. Tests: node pseudoKind + compare ends; pins.
7. CHANGELOG + help.
