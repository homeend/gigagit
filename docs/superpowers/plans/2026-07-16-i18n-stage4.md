# TUI Multilanguage Stage 4 (Terminal Chrome Sweep) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route 100% of remaining user-visible TUI text through `i18n.T` (pair-op picker, ~14 chrome surfaces, ~18 textfield popups, ~85 action-menu labels), land three carried code fixes (notice staleness, "working changes" arg, pad overflow), and add a menu-label enforcement gate.

**Architecture:** Identical mechanism to stages 1–3: English-text-as-key `i18n.T(key, args...)` over four embedded bundles; the existing `i18n_scan_test.go` gate enforces literal keys, all-four-bundle coverage, orphan-freedom, and verb match automatically for every key the waves add. New: `menu_labels_test.go`, an AST gate in the `options_vocab_test.go` style for action-row labels.

**Tech Stack:** Go 1.26, Bubble Tea/lipgloss, TOML bundles under `internal/i18n/lang/`, go/ast for the gate test.

**Spec:** `docs/superpowers/specs/2026-07-16-i18n-stage4-design.md`

## Global Constraints

- Every new `i18n.T` key is added to ALL FOUR bundles (`internal/i18n/lang/{ja,ko,zh,ru}.toml`, under `[strings]`) **in the same commit**. Bundles are NOT sorted — insert near related keys, never re-sort.
- A replaced/deleted key is removed from all four bundles (the scan test's orphan check fails otherwise).
- `i18n.T` keys must be string LITERALS at the call site (scan test enforces). Literals reaching the UI through helper returns/params wrap at the DEFINITION site.
- Protocol values never translate: decision `Options` values, config keys/values, op/source names, notice ids, `[refresh]` row names.
- Footer hint strips are the sanctioned fragment-concatenation exception (list-like; conditional tokens are their own keys; leading spaces load-bearing). Key-cap tokens like `[enter]`, `[esc]`, `[↑/↓]` stay verbatim inside the key; only the words after them translate.
- Concatenated prose becomes a format key (`i18n.T("Check out %s as", ref)`). Translations may reorder arguments ONLY via indexed verbs (`%[2]s` … — `CheckVerbs` range-checks these at load).
- Never `len()`/`%-Ns` on translated strings — use `padCell`/`lipgloss.Width`/`maxCellWidth` (Task 11).
- Engine/CLI prose (`internal/engine`, `internal/cli`) untouched.
- Initial translations: match each bundle's existing glossary — before translating a term, grep the bundle for keys already using it (e.g. how ja renders "merge", "worktree") and reuse that rendering. The per-language QA tasks (12–15) refine.
- Verification per wave task: `gofmt -l internal/` (empty), `go vet ./...`, `go test ./internal/tui/ ./internal/i18n/ -count=1`, `go build ./cmd/gg`.
- Work on branch `feat/i18n-stage4` in worktree `/mnt/t/others/gigagit/.claude/worktrees/i18n-stage4` — verify with `git branch --show-current` before editing.

// rebuildNotices re-derives m.notices from the cached health snapshot.
// Notice titles/details/action labels bake i18n.T output at build time, so a
// language switch must rebuild them; ids are stable, so dismissals hold and
// no blink logic runs here (applyRepoHealth owns blinking).
func (m Model) rebuildNotices() Model {
	if !m.repoHealthKnown {
		return m // nothing cached yet: the first health read builds in the new language
	}
	var dismissed map[string]bool
	if m.promptStore != nil {
		dismissed = m.promptStore.DismissedNotices(m.repoHealth.GitCommonDir)
	}
	var next []notice
	if n := commitGraphNotice(m.repoHealth); n != nil && !dismissed[n.id] && !m.noticeSessionDismissed[n.id] {
		next = append(next, *n)
	}
	if n := clipboardNotice(m.clipAvail, m.repoHealth.GitCommonDir); n != nil && !dismissed[n.id] && !m.noticeSessionDismissed[n.id] {
		next = append(next, *n)
	}
	m.notices = next
	return m

// maxCellWidth returns the widest display width among labels, floored at min —

func maxCellWidth(min int, labels ...string) int {
