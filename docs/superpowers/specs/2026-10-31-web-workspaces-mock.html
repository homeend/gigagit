                                          commit rowopen its files + diff; the yellow Working tree row (appears at the top while the tree is dirty) opens the status view: stage/unstage buttons per file, stage-all/unstage-all, commit box, stash
                                          
    
                                          interactive rebasedrag a branch onto another → interactive rebase A onto B… opens a plan editor listing every commit A has that B does not, newest first. Per row choose pick (keep), reword (edit the message — the editor opens straight away), squash (meld into the commit below it) or drop, and move rows with ↑/↓. Nothing runs until you press start: cancel, esc and clicking outside all leave the branch untouched. If the branch moves while the editor is open the plan is refused rather than applied to a history that changed
                                          
    
                                          commit right-clickshow it, copy its commit id or subject, and act on it. create tag here… opens one dialog with both fields — the tag name, and a message under it (tab moves between them). Fill the message in and you get an annotated tag, ready to push from the Tags section; leave it empty and you get a lightweight one, exactly as in the TUI. create branch here… is the usual create-branch dialog (prefix lane included) starting at this commit; fast-forward <branch> to here advances the current branch when this commit is strictly ahead of it (git refuses otherwise); reset <branch> to here… opens the soft / mixed / hard picker, cancel included. create worktree here… opens the create-worktree dialog at this commit (see new worktree). cherry-pick onto <branch> applies this commit's change to the current branch and revert this commit adds its inverse on top — both confirm first, and a conflict parks the keep/abort decision in the modal. edit commit message… opens the commit's WHOLE message (subject and body) in a multi-line box — ctrl+enter confirms, since enter types a newline there. review this commit (AI)… scopes a review to this commit's own change. A commit with an agent's permanent overview (a ≡ marks it, on any branch) lists it in its files under Overviews, below its Reviews: a click opens it — the overview on the left, the file at the commit on the right with the overview's remarks; right-click: open / export as HTML (one self-contained file to share outside gg: the files its links name and their diffs, no notes) / copy gg link / delete. A branch whose tip is that commit lists it as a └ Overview row under it too. History edits: move up / move down swaps the commit with its neighbour, drop this commit removes it (confirmed first, shown red). Both rewrite the checked-out branch from that commit up by replaying the commits above it, so they are offered only on an ordinary commit — not a merge — and the branch is left untouched when the commit is not on it. The previous tip is recorded, so the branch's previous versions… can put it back

A configured worktree post-create hook is shown for approval before it runs
                                          
    
                                          compare two branchesdrag a branch onto another → compare A ↔ B lists every file that differs between the two tips. The bar above the file list filters by origin: only the files one side changed since the branches diverged (a file both sides touched shows in either). Without a common ancestor the list still opens — only the filter is unavailable
                                          
    
                                          two change-sets, side by sidea link comparison of two SETS (two previews, a pair against a preview, two agents' attempts) offers ⇄ symmetric (v): each set's file list on its own side, row for row — a gap where a set does not touch the file, a struck-through row where it DELETES it, and a dimmed = row where both changed it identically. One diff sits between them; the arrow over it (x) flips which set is old and which is new — the lists stay put. 1–4 filter: differ · all · one side · same. It needs a window at least 1200px wide and is remembered.

The review runs in the task scheduler (ctrl+\ → AI tasks) and opens as its review when it is done

                                          reflogthe sidebar's last section lists where HEAD has been (HEAD@{0} is newest) — commits survive here even after a reset or rewrite. Click: show that commit · right-click: show, copy its sha, check out here (detached, or as a new branch), reset the current branch to it (pick soft / mixed / hard in the modal; cancel is always offered), and bookmark or shelf the commit so a lost one stops being lost. The section opens on the newest 100 entries; the … show 100 more row at the bottom loads the next page, and stays expanded through refreshes
                                          
    
                                          bookmarks · shelfgg's own stores, not git's — the two sections below the reflog (folded until you open them). A bookmark is a LIVE reference to a commit or a file: it follows later edits, and it survives the branch it lived on being deleted. A shelf entry is a FROZEN copy — a file's bytes, or a commit's changed files — so it outlives a rewrite, a gc, even deleting the source. Right-click a commit or a file anywhere (the commit list, the reflog, the files pane) → bookmark this… / shelf this…; a commit entry asks for a name, prefilled with its subject. Each row leads with its kind — F a file, C a commit, S a shelved set of files — then the TUI switcher's text (where it lives / its commit or state / its path, and a name), the path cut in the middle so the file name stays. Click runs the first menu row; right-click is the TUI switcher's (g / G) actions: a file entry diff against the working-tree file, paste to a path… (a bookmark writes what it points at TODAY) or restore to a path… (a shelved file, prefilled with its original path), copy to a new dir under <repo>.tmp…, copy path… (path, absolute path or file name); a commit bookmark compare against the selected commit and cherry-pick onto the current branch; a shelved commit or set browse the frozen files and restore a file… (and a commit cherry-pick, a real one while the commit exists, from the patch frozen alongside the files once it does not); the gg link, compare with another entry…, view note on a ◆N shelf row (notes gg left: a recycled worktree's deleted and renamed files), then file history / show commit and remove

                                          list ordereach of branches, remotes, worktrees and tags carries a small chip at the right of its section header showing how it is sorted — click it to cycle git (git's own order) → name↑ → name↓ → date↑ → date↓, the TUI's o key. Branches start on date↓, so the branch you touched last sits at the top; tags have no date of their own, so they offer the name orders only. Clicking the chip never folds the section. Remotes and tags are capped at 100 rows and the order is applied before that cap — date↓ there means the 100 most recently updated, not the first hundred re-shuffled. The working-tree file list has the same chip in its own header (or the o key). Every order is remembered per machine (on a random port the browser cannot remember it itself)

The choice is remembered per repo and shared with the TUI. The checked-out branch, branches checked out in a worktree and the current upstream are never hidden (∗ marks one the rule would hide). Remotes filter before the 100-row cap

                                          compare with linkcompare with link… (the command palette, or the ☰ menu) compares any two gg:// links — a branch, a commit, a stash, a file at a revision, a change-set, the working tree. Paste one link in each field; enter moves on and then compares, esc closes. ↓ (or ▾) lists the links you copied — in the web, the TUI or the CLI — and a pick fills the field without comparing. ctrl+s (or ⇅ swap) exchanges the two sides. A base row appears under a link to a branch, a tag or a whole commit, prefilled with its upstream (else the trunk), or the commit's parent: enter on it (or bound) rewrites the link to the files a merge into that base would change — @base...branch — or to what the commit changed. Nothing is rewritten until you do; leaving it alone compares the whole tips. An error is shown under the field it belongs to. The result opens as a comparison: every file that differs, each with its diff. save comparison… on its bar keeps it in the Previews tab (an empty label takes the default)
                                          alt+↓ · alt+↑ · search historyin the commit filter (/, @), an in-view search and the file finder: alt+↓ puts the last confirmed query back, again for older ones, alt+↑ for newer ones and, past the newest, what you were typing. A query is remembered when you press enter — per repository, shared with the TUI
                                          / · @ · ] · [ · in-view searchin an open diff, in the conflict picker, in the blame overlay, in an open file or an overview (either column of the split, the stacked files across every file read so far), or in this help: / searches the visible text forward, @ backward (case-insensitive; in changes only mode the folded lines are not searched — unfold or press f). Typing scrolls to the nearest hit as you go and the bar counts hit/total; enter keeps the query and hands the keys back to the view, ] / [ step to the next / previous hit (wrapping), esc while typing puts the view back where it was, esc on a kept query clears it — only the next esc leaves the diff or closes blame / help / the overview. Every hit is tinted, the current one brighter — the TUI's / @ ] [ in its diff, blame and preview views
                                          external editorthe server's $VISUAL / $EDITOR (vi, or notepad on Windows) runs in a console over the panes, as the terminal's editor takes the terminal: a working-tree file's edit in editor edits the file itself (the list reloads when the editor exits — edited f.txt); open staged version in external editor, a commit file's open in external editor, a bookmarked or shelved file's, and I on a commit (its message) open a read-only copy, removed when the editor exits (viewed f.txt). In a diff e (or the menu's open in editor at line N) opens it at the clicked line: the working file for a working-tree diff, a copy of the shown version for a commit's — not on a two-sided compare. e in the file history opens the selected commit's version, in blame the blamed one. The editor gets the line as +N (vi, nano, emacs…), --goto path:N (code, cursor) or path:N (hx, subl, zed)
                                          quitting gg webCtrl+C in the terminal running gg web quits it. With agents or AI tasks still running it asks first — in the terminal and here, in the ctrl+\ switcher: Q (or a second Ctrl+C) ends the AI tasks, then the agent sessions, and quits; esc cancels (the next Ctrl+C asks again). A page gg's terminal UI serves quits with it. On a page opened from the terminal, Switch to TUI (☰ menu or palette) hands control back: one interface is active at a time, and this page shows a notice with Activate web UI and Quit until you return. The ☰ menu's last row, quit gg…, quits from the page: it asks first (naming the agents and AI tasks it would end) and, on a page the terminal UI serves, quits the terminal UI too.
