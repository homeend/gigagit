                          gg web — keys & features
                          
    
                          Keys
                          
    
                          j / k · ↓ / ↑move the selection (commit list, or file list in detail)
                          
    
                          enteropen the selected commit (file list appears right) / open the selected file (diff)
                          
    
                          escone stage back — diff → file list → commit list; closes menus and modals (in a decision modal: abort, when offered)
                          
    
                          gcommit graph on/off — off is a flat list, more room for subjects (persisted)
                          
    
                          rrefresh everything (status, branches, commits) — also happens automatically when the tab regains focus
                          
    
                          bshow / hide the sidebar (persisted)
                          
    
                          ppull the current branch (confirms first; conflicts and forks arrive in the modal)
                          
    
                          Ppush the current branch (rejection recovery — rebase / force — in the modal)
                          
    
                          s / ustage / unstage the focused file (working-tree status view)
                          
    
                          m · ctrl+clickmark / unmark status files for a batch — right-click then offers stage / unstage / discard N marked (discard is all-or-nothing: a stale mark refuses the whole batch); conflict rows can't be marked
                          
    
                          ctrl+entercommit, from the message box
                          
    
                          /filter the commit list — subject, author, or sha prefix, over the loaded rows; ctrl+enter searches deeper (loads more commits); esc clears it
                          
    
                          #goto commit — jump to a sha, branch, tag, or any rev, paging the list deeper if needed
                          
    
                          ?this help
                          
    
                          ctrl+k / ctrl+pcommand palette (incl. switch repo)
                          
    
                          Mouse
                          
    
                          commit rowopen its files + diff; the yellow Working tree row (appears at the top while the tree is dirty) opens the status view: stage/unstage buttons per file, stage-all/unstage-all, commit box, stash
                          
    
                          interactive rebasedrag a branch onto another → interactive rebase A onto B… opens a plan editor listing every commit A has that B does not, newest first. Per row choose pick (keep), reword (edit the message — the editor opens straight away), squash (meld into the commit below it) or drop, and move rows with ↑/↓. Nothing runs until you press start: cancel, esc and clicking outside all leave the branch untouched. If the branch moves while the editor is open the plan is refused rather than applied to a history that changed
                          
    
                          commit right-clickshow it, copy its commit id or subject, and edit history: move up / move down swaps the commit with its neighbour, drop this commit removes it (confirmed first, shown red). Both rewrite the checked-out branch from that commit up by replaying the commits above it, so they are offered only on an ordinary commit — not a merge — and the branch is left untouched when the commit is not on it. The previous tip is recorded, so the branch's previous versions… can put it back
                          
    
                          branchclick: jump the list to its tip · right-click: switch, pull / push it, merge it into the current branch, rebase the current branch onto it (the drag pair-ops as plain rows) or fast-forward the current branch to it (refused unless it is strictly ahead), copy its name / tip commit id / worktree path, delete · drag onto another branch: merge or rebase
                          
    
                          make a branchright-click a branch → rename, create branch from here, or create worktree for this branch (only when it has none). Each asks in a one-line prompt: enter confirms, esc cancels. A configured worktree post-create hook is shown for approval before it runs
                          
    
                          compare two branchesdrag a branch onto another → compare A ↔ B lists every file that differs between the two tips. The bar above the file list filters by origin: only the files one side changed since the branches diverged (a file both sides touched shows in either). Without a common ancestor the list still opens — only the filter is unavailable
                          
    
                          force pushright-click a branch → force push… asks which kind before doing anything: force-with-lease (refuses if the remote moved since your last fetch) or plain force (overwrites regardless), both red, plus abort. The same prompt you get when an ordinary push is rejected — this row just reaches it without waiting for the rejection
                          
    
                          previous versionsright-click a branch → previous versions… lists what it pointed at before each recent operation (merge, rebase, amend, reset, delete…). Click one to restore the branch to it, copy its commit id, or delete the snapshot. Restoring is itself recorded, so it can be undone the same way
                          
    
                          review (AI)right-click a branch → review … (AI) runs a configured review agent over that branch's work; the ☰ menu and palette carry review working changes. gg names a tool, never a command: the command comes from your own [[tools.command]] config with category = "review", is shown in full for approval before its first run, and the approval is remembered per repo until you edit it. The report is shown when it finishes and also saved to a file, whose path the viewer shows
                          
    
                          background a runa review takes minutes, so you do not have to watch it: run in background (or esc, or clicking outside the box) hides it and leaves it running. A chip appears in the top bar; click it to watch or cancel the run. When the report is ready the chip fills and blinks — click it to read the report, which waits there until you do. Backgrounding never cancels; only the labelled cancel the run button does. The run still holds the operation lane, so reading the repo works normally but a second operation waits until it finishes
                          
    
                          solo a branchright-click a branch → solo this branch narrows the commit list to that branch's history. A solo: name ✕ chip appears in the top bar — click it (or the menu's exit row) to show every branch again. The scope belongs to the server, so every tab sees it, and it survives commits, merges and pulls until you clear it
                          
    
                          pull a branchpulling a branch you are not on updates it in place and leaves you where you are — no checkout, nothing to confirm. Pulling the branch you are on asks first, since it can rewrite the working tree
                          
    
                          remote branchthe sidebar's remotes section lists remote-tracking branches. Click: show its tip commit · right-click: check out as… / switch to as… (materialize under a local name, fast-forward-safe), merge into the current branch, rebase the current branch onto it, reset the current branch to its tip (only on the current branch's own counterpart; confirmed — discards local commits and uncommitted changes), copy name / commit id, delete from remote (confirmed first). fetch all remotes and prune remotes live in the ☰ menu and palette
                          
    
                          worktreeright-click: switch here (re-root the server), copy path / branch name, remove
                          
    
                          tagclick: show its commit · right-click: show, check out (detached, or as a new branch via prompt), solo this tag (narrow the commit list to its history — the top-bar chip exits, same as branch solo), copy name / commit id, annotate (set or replace the message, keeping the target), push tag / delete from remote (the remote is picked for you when there is one; deleting confirms first), delete
                          
    
                          make a tagright-click a commit → create tag here… makes a lightweight tag at that commit; annotate it afterwards from the tag's own menu
                          
    
                          stashclick: show its changes (incl. untracked) · right-click: apply, pop, drop
                          
    
                          reflogthe sidebar's last section lists where HEAD has been (HEAD@{0} is newest) — commits survive here even after a reset or rewrite. Click: show that commit · right-click: show, copy its sha, check out here (detached, or as a new branch), reset the current branch to it (pick soft / mixed / hard in the modal; cancel is always offered)
                          
    
                          change blockin an unstaged file's diff: click a highlighted block to select it, then stage selected in the diff header stages just those hunks
                          
    
                          status fileright-click: stage / unstage, stage all / unstage all, copy path / absolute path / file name, add an untracked file (or its extension) to .gitignore, discard — per file, the marked set, or all
                          
    
                          settings☰ → settings… (also in the palette): grouped panel — commits (show graph, commit sort, commit-graph file), refresh (TUI), history & logs (operations-history snapshots + retention, operation log), repo (active settings file, worktree post-create hook). Every change saves immediately to the right config file — per-repo keys to the repo's settings file, machine keys to the global one. External tools and language remain in the TUI settings for now
                          
    
                          identity☰ → identity & profiles… (also in the palette): current git user.name/email per scope (global · repo · effective), edit-and-apply to this repo or globally, and named identity presets — create, edit, delete, apply. Presets are gg-local; only an apply touches git config
                          
    
                          prefixes☰ → branch prefixes… (also in the palette): manage the templated branch-name skeletons (global · per-repo; tokens like <user:LABEL>, <seq:NAME:N>, <date>, <parent-branch>). new branch… on a row fills any <user:…> labels, resolves the name against the live repo and opens the create-branch prompt prefilled (still editable); <seq> counters advance only when the create succeeds
                          
    
                          ☰ menugrouped: git (pull, push, fetch, prune, create branch, versions, review, identity, prefixes) · ui (refresh, switch repo, palette, sidebar, graph, settings) · help
                          
    
                          section headerdouble-click: collapse / expand that sidebar section (persisted)
                          
    
                          pane dividerdrag to resize — the sidebar in the commit list, the file list in a commit's detail · double-click resets it (persisted)
                          
    
                          bottom barthe footer entries are clickable — pull, push, refresh, stage/unstage, graph, sidebar, help
                          
    
                          diff header ‹ ›previous / next file · previous / next change block
                          
    
                          ☰global menu (top-left) — pull, push, fetch all remotes, create branch, refresh, switch repo, toggles
                          
    
                          Notes
                          
    
                          decisionsoperations pause mid-flight and ask in the modal; destructive options render red; esc aborts when an abort option exists
                          
    
                          connectiona dropped stream reconnects and replays; if the server is gone the op line reports it and the UI unlocks
